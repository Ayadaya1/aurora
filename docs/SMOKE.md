# Smoke и состояние релиза Nord Scan

## Статус на 28 сентября 2026

**Кандидат 1.0.0+4 ещё не собран в RPM и не прошёл повторный smoke.**
Linux-сервер сборки недоступен; пользователь попросил продолжать без него.
Пакеты **1.0.0+3 нельзя публиковать**: галерея и камера не открываются из-за
несовместимого оконного плагина. Успешная компиляция и rpm-validator этого
runtime-дефекта не обнаруживают.

## Выполнено

- Standalone Aurora Emulator 5.2.1.200/aarch64 установлен на Mac Apple Silicon.
  Для запуска QEMU применён `-machine highmem=off`, память 2048 МиБ.
- RPM 1.0.0+3 установлен через sdk-deploy-rpm, запущен в штатной песочнице
  Runtime Manager с выводом консольного лога.
- Иконка Nord Scan и имя приложения отображаются. Онбординг не повторяется
  после завершения, основной экран открывается без прежнего падения CEF.
- Галерея и камера возвращают понятную ошибку, приложение остаётся открытым.
  Консоль: `PlatformException(Method "CreatePopupWindow()" is not provided by
  the loaded API.)`. Патч пустого цвета темы устранил лишь первое исключение.
- Рисование не работало; отдельный Flutter-тест воспроизвёл отсутствие штрихов.
  В исходниках 1.0.0+4 обработка переведена на pointer-события: изменение
  ScrollPhysics больше не отменяет ожидающий pan. Одиночные точки рисуются.
- Шесть тестов приложения прошли на upstream Flutter 3.41.7: ошибки picker и
  повторная попытка, холст/очистка, онбординг, обычные формулы, fallback/copy,
  прокрутка длинной формулы.
- 21 сентября: обе архитектуры 1.0.0+3 собраны Flutter Aurora 3.41.4, SDK
  5.2.1.200, прошли `rpm-validator --profile regular`. После скачивания
  совпали SHA-256. Информационные сообщения о symlink допустимы.
- 21 сентября: 12 тестов backend прошли, API готов после прогрева;
  служба aurora-formula.service включена для автозапуска. Замеры приведены
  в `server/README.md`. 28 сентября сервер недоступен, повторного API-smoke нет.

## Подготовленное исправление окон

В third_party закреплён aurora_window_manager **1.8.0** с защитой от пустых
цветов. Он использует встроенный канал `flutter/aurora-window-manager`, наличие
которого проверено в реально установленном libaurora_embedder.so.
Версия 1.10 использует новый native API, отсутствующий в этом embedder.
Вызовы image_picker_aurora 2.4.0, file_selector_aurora 1.5.2 и aurora_controls
1.3.1 сверены с API 1.8.0. Тесты канала находятся в `tools/compat_tests`.
Все три теста прошли: пустой, невалидный и корректный цвет темы;
вызов createWindow и передача результата через прежний канал.
Это проверка исходников/контракта, **не подтверждение работающей галереи в RPM**.

## Следующий обязательный этап

1. Включить сервер и синхронизировать ветку codex/aurora-os-release, сохранив
   текущие незакоммиченные изменения на сервере перед переключением.
2. В `/home/aurora-build/aurora-server` выполнить
   `runuser -u aurora-build -- ./tools/build-aurora.sh all`.
   Скрипт временно устанавливает Aurora-only overrides; lockfile обновлён
   для path-пакета 1.8.0, воспроизводимость должен подтвердить pub get.
3. Установить 1.0.0+4 и проверить: галерея → выбор PNG → предпросмотр,
   камера → снимок либо корректное сообщение об отсутствии камеры, закрытие
   и повторное открытие диалога, рисование/очистка, распознавание → формула/copy.
4. Пройти то же на физическом устройстве; ARM32 пока проверен только сборкой.
5. Для магазина задать реальный application/organization ID и подписать RPM
   сертификатом источника. Текущий `com.example.aurora` — шаблонный ID,
   пакеты не имеют публикационной подписи. Иконка 266×266 готова, остальные
   требования конкретного магазина отдельно не проверялись.
